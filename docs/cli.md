# Assetloom CLI

All commands accept one or more `--config` files in merge order and an optional
`--target`. Add `--json` for a stable machine-readable envelope and `--verbose`
for diagnostic stacks.

```sh
assetloom plan -c assetloom.json [--target <id>]
assetloom generate -c assetloom.json [--target <id>] [--report]
assetloom verify -c assetloom.json [--target <id>] [--native]
assetloom clean -c assetloom.json [--target <id>]
assetloom report -c assetloom.json [--target <id>] [-o <file>]
```

## Configuration versions

Schema version 1 retains the original native-only behavior. Target values are
`android` and `ios`; every command delegates to the original native API, so its
plan task shape, output messages, cache, manifest, and generated bytes remain
compatible with Assetloom 0.1.

Schema version 2 accepts any target ID declared by the configuration. Its plan
JSON uses `plan.artifacts` because outputs may be copied files, transformed SVG
components, image variants, generated text, or safe project integrations. The
generate, verify, clean, and report commands use the same target filter.

Generation is repeatable: an unchanged second run reports files as unchanged.
Cleanup removes only outputs recorded as Assetloom-owned and reverts only the
managed portions of authored project files. Verification checks stored hashes,
image structure, font signatures, and managed integration receipts.

## Exit codes

- `0`: success, help, or version output.
- `1`: configuration, planning, generation, verification, or ownership error.
- `2`: invalid CLI usage.

Errors written with `--json` contain `ok: false` and a stable Assetloom error
code. Successful JSON results contain `ok: true`.
